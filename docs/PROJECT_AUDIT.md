# ChemVision AI project audit

Audit date: 2026-10-20 (follow-up)

This audit describes the checked-in workspace, not the assumptions in the supplied project brief. Evidence was gathered from the README, backend routes/models/services, frontend pages/scripts/styles, ML artifacts, and the bundled COCO dataset manifests. No browser session or external credentials were available during this source audit.

Follow-up verification: this directory is not a Git worktree (`git status` reports no repository), so no baseline diff or commit history was available. The project environment is `backend/.venv` (Python 3.12.14; CPU-only PyTorch 2.14.0; torchvision 0.29.0; RDKit 2024.9.4). An isolated `unittest` smoke suite passes three tests for dataset accounting, RDKit structure generation/invalid SMILES, and signup/auth, authenticated image ownership, flashcard persistence, quiz scoring/history, and profile aggregation. It uses a temporary SQLite database; the existing `backend/app.db` was not opened by tests. The landing page was checked in a browser at its default viewport: the dark theme applies, the accessible toggle label updates, and the preference survives reload. Other-page and mobile browser QA remain unverified; deployment was not performed.

## Architecture found

- Frontend: static HTML pages with vanilla JavaScript and a shared `app.css` stylesheet. Pages include home, signup/login, dashboard, molecular studio, flashcards, quiz, reaction visualizer, and profile.
- Backend: FastAPI, SQLAlchemy 2, Pydantic, JWT bearer authentication, SQLite by default and a PostgreSQL URL option.
- Chemistry: OpenCV + EasyOCR image text extraction; a known-reaction registry; RDKit parsing and conformer generation; Three.js renderers for molecule and reaction views; optional PubChem lookup.
- Learning data: SQLAlchemy tables and seed data for flashcards, review state, quiz questions/choices, quiz attempts/responses, saved molecules, and reaction uploads.
- ML: EfficientNet-B0 image classifier adapter and checkpoint at `backend/models/chemvision_classifier/`. The saved evaluation report records 1/21 correct (4.76%) and 4/21 top-3 (19.05%). This is not reliable enough to establish reaction identity.
- Dataset: `CHEMVISION.v7i.coco` has 153 train, 14 validation, and 54 test images, each with one valid annotation and 89 raw categories across manifests. Train-derived classes cover 6/14 validation and 21/54 test images. Filenames show source document `pdf1` represented in every split, so source-group leakage is plausible. The provided license statement is CC BY 4.0. This is reaction-class/region labeling, not atom-level structure transcription. Sample-level statistics are at `docs/dataset_report.json`.

## Follow-up ML and deployment corrections (2026-10-20)

- Added `ml/audit_dataset.py` and a sample-level dataset report. It verified that 221/221 images decode and have exactly one annotation, with zero exclusions. Labels remain split-disjoint: validation has 4 unseen canonical classes (8 images); test has 31 unseen canonical classes (33 images).
- Changed `ReactionDataset` to fail rather than silently filter samples for invalid images, missing/unknown labels, duplicate IDs, or incomplete/multiple annotations.
- Changed training checkpoint selection to validation macro-F1 and removed unconditional final-epoch overwriting. Training aborts before fitting on the current invalid validation/test manifests; no retraining or new accuracy is claimed.
- Added production config checks: `ENVIRONMENT=production` requires a non-placeholder JWT secret and explicit HTTPS frontend origins, and disables development `null`/localhost CORS allowances.
- Removed public static access to uploaded images. Reaction images now require the owning user's authentication; deleting an owned reaction also removes its contained upload file.
- Added a persistent, accessible dark-mode toggle to the landing page, with theme initialization before page styling; verified the selected theme and preference after reload.
- Added `docs/ML_MODEL_AUDIT.md` and `docs/DEPLOYMENT_GUIDE.md` with data, checkpoint, metric, environment, and hosting limitations.

## Important limitations

1. The bundled classifier has poor recorded held-out performance and should not drive automatic reaction identification.
2. The COCO dataset has one annotation per image across 89 raw categories and is too small/sparse to support reliable reaction recognition claims. It contains no molecular graph transcription labels.
3. EasyOCR output and registry matching are not a validated chemical equation OCR system. A recognized equation must be confirmed by the user before relying on it.
4. Reaction visualization depicts registry reactant/product structures and an educational stage animation. It is not a molecular dynamics simulation or reaction mechanism engine.
5. The app currently has no schema migration framework, no integrated sketcher, no complete export workflow, and no automated regression suite.

## What is needed from the project owner

No additional input is needed to continue the source-level audit and independent fixes. For a production-grade chemistry recognition pipeline, the owner will need to provide or approve a larger correctly labeled dataset with redistribution rights; compute resources are only needed if training/fine-tuning is desired. Production deployment also needs a secure `JWT_SECRET_KEY`, chosen database, frontend origin list, and hosting/upload-storage configuration. Those secrets should be entered into the deployment environment, not pasted into chat.
